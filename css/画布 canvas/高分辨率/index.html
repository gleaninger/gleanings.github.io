绘制​

在高分辨率的显示屏（ window.devicePixelRatio > 1 ）中，如果按照 CSS 像素绘制导致视觉效果模糊。

而核心处理方法就是：把 Canvas 的物理像素放到大 CSS 像素 * devicePixelRatio 处，然后把 Canvas 缩放到 CSS 尺寸。这样仍然按照 CSS 像素画图，但每一个逻辑像素都会落到整数个物理像素上，会面就不会被浏览器二次拉伸。

function setupCanvas(canvas) {
  const dpr = window.devicePixelRatio || 1;
  const rect = canvas.getBoundingClientRect();

  // CSS 显示尺寸
  canvas.style.width = `${rect.width}px`;
  canvas.style.height = `${rect.height}px`;

  // 物理像素尺寸
  canvas.width = Math.floor(rect.width * dpr);
  canvas.height = Math.floor(rect.height * dpr);

  const ctx = canvas.getContext('2d');
  ctx.scale(dpr, dpr);

  return ctx;
}

之后绘制仍然使用 CSS 像素坐标：

const ctx = setupCanvas(document.getElementById('myCanvas'));

ctx.fillStyle = '#333';
ctx.fillRect(0, 0, 200, 100); // 这是 CSS 像素
为什么这样会清晰

Canvas 有两套尺寸：

尺寸物理像素CSS 像素
宽canvas.widthcanvas.style.width
高canvas.heightcanvas.style.height
作用实际像素缓冲区大小页面布局里的现实大小

如果只设置 CSS 尺寸，不放大 canvas.width/height, 浏览器就会把低分辨率缓冲区拉伸到高分辨率屏幕上，出现模糊。

容易踩的几个坑​

  • 只放大 canvas.width/height 而不 ctx.scale() ：所有的坐标、线宽、字体都需要乘 dpr
  • 不要同时 transform: scale() 和 ctx.scale ：容易双重缩放
  • 窗口大小或 DPR 变化时要重设 ：比如切换显示器、缩放比例变化、设备旋转 
    let currentDpr = window.devicePixelRatio || 1;
    window.addEventListener('resize', () => {
      const dpr = window.devicePixelRatio || 1;
      if (dpr !== currentDpr) {
        currentDpr = dpr;
        render(); // 重新 setupCanvas + 重绘
      }
    });
    // 更精细的 DPR 监听
    const mq = window.matchMedia(`(resolution: ${currentDpr}dppx)`);
    mq.addEventListener('change', () => render());
  • 坐标尽量取整 ：尤其是 1px 线条 
    ctx.fillRect(Math.round(x), Math.round(y), w, h);
  • 图片绘制是时也要考虑 DPR ：如果源图本身分辨率低，放大后依然模糊。可以准备 @2x 图，或者设置： 
    ctx.imageSmoothingEnabled = true;
    ctx.imageSmoothingQuality = 'high';
  • 像素艺术/需要硬边缘时 ：可以关闭平滑 
    ctx.imageSmoothingEnabled = false;

封装​

class HiDpiCanvas {
  constructor(canvas) {
    this.canvas = canvas;
    this.ctx = canvas.getContext('2d');
    this.dpr = window.devicePixelRatio || 1;
    this.resize();
  }

  resize() {
    const rect = this.canvas.getBoundingClientRect();
    this.canvas.style.width = `${rect.width}px`;
    this.canvas.style.height = `${rect.height}px`;
    this.canvas.width = Math.floor(rect.width * this.dpr);
    this.canvas.height = Math.floor(rect.height * this.dpr);
    this.ctx.setTransform(this.dpr, 0, 0, this.dpr, 0, 0);
  }

  update() {
    const dpr = window.devicePixelRatio || 1;
    if (dpr !== this.dpr) {
      this.dpr = dpr;
      this.resize();
    }
  }
}

用 ctx.setTransform(dpr, 0, 0, dpr, 0, 0) 比连续 scale 更稳，避免多次初始化时叠加变换。

重绘性能优化​

Canvas 重绘性能优化的核心思路是：较少每帧的绘制量、减少重复计算、把重活从主线程移走、避免触发低效渲染路径。

优先减少重绘范围​

不要每帧都无脑 clearRect(0, 0, width, height) 再全量重绘。

  • 脏矩形更新 ：只清除和重绘更新有变化的部分
  • 视口剪辑 ：只绘制可见部分，不可见对象直接跳过
  • 状态变化才重绘 ：如果数据没变、位置没变、样式没变，就不要重新绘制

分层渲染​

把不同更新频率的内容放到不同 Canvas 上：

  • 背景图 ：静态背景、网格、地图，初始化画一次即可
  • 中间层 ：低频变化的 UI、坐标轴、图例
  • 顶层 ：高频动画、游标、粒子、拖拽反馈

离屏 Canvas 渲染​

对复杂但是变化少的图形，先画到离屏 Canvas ，再在主循环里 drawImage ：

const offscreen = document.createElement('canvas');
offscreen.width = width;
offscreen.height = height;
const offscreenCtx = offscreen.getContext('2d');

drawComplexShape(offscreenCtx); // 渲染复杂图形

// 主循环里直接贴图
ctx.drawImage(offscreen, 0, 0);

drawImage 贴图通常比每帧重新执行大量路径绘制更快，因为它更接近 GPU 纹理合成路线。

合并绘制调用​

减少状态切换和 API 调用次数：

  • 同色、同样式对象尽量合并到一个路径里
  • 避免频繁切换 fillStyle 和 strokeStyle、 lineWidth、 font
  • 多条线尽量用一条折线路径，而不是多次 moveTo/lineTo
ctx.beginPath();
ctx.fillStyle = '#4a80d9';
for (const node of sameColorNodes) {
  ctx.rect(node.x, node.y, node.width, node.height);
}
ctx.fill();

使用 requestAnimationFrame​

动画不要用 setInternal / setTimeout，而是用 requestAnimationFrame ：

function animate() {
  ctx.clearRect(0, 0, canvas.width, canvas.height);
  // ...
  requestAnimationFrame(animate);
}
requestAnimationFrame(animate);

坐标取整，避免亚像素渲染​

浮点坐标会触发抗锯齿和子像素计算：

ctx.fillRect(Math.floor(x), Math.floor(y), w, h);
ctx.drawImage(img, Math.floor(x), Math.floor(y));

避免高开销 API​

有些 API 会明显拖慢渲染：

  • shadowBlur ：大量对象带阴影时非常耗费性能
  • 频繁 globalCompositeOperation 切换
  • 每帧大量 fillText
  • 每帧用 drawImage 缩放图片，最好提前生成目标尺寸缓存

高 DPR 下要控制分辨率​

前面说的 devicePixelRatio 适应并不是无脑乘。 3x 、 4x 屏幕会让 Canvas 位图体积暴涨，显存和合成成本都会上升。

可以加一个上限：

const dpr = Math.min(window.devicePixelRatio || 1, 2);

必要时使用 OffscreenCanvas/Worker​

如果绘制逻辑很重，可以把渲染放进 Worker 中：

const offscreen = canvas.transferControlToOffscreen();
const worker = new Worker('worker.js');
worker.postMessage({ canvas: offscreen }, [offscreen]);

这样主线程不会被绘制阻塞， UI 交互会更流畅。
